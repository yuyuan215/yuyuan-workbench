# 私人 AI 综合工作台 · 云端部署指南

> 目标：把整套静态网页系统部署到云端，**不依赖本地电脑、关机后 7×24 小时可用**，支持公司内网 / 公网访问，自带登录鉴权与账号权限。

---

## 一、部署前准备

整套系统是一个**纯静态站点**，没有任何后端、没有数据库、没有构建步骤。出包内容就是 `ai-workbench/` 这一个目录：

```
ai-workbench/
├── index.html          # 登录页
├── app.html            # 工作台主界面
├── manifest.json        # PWA 清单（App 名称/图标/全屏配置）
├── sw.js               # Service Worker（离线缓存、可安装为 App）
├── assets/
│   ├── icons/icon.svg  # 淡蓝品牌图标（六大板块拼图）
│   ├── css/style.css   # 全站样式（含浅色/深色主题）
│   └── js/
│       ├── core.js     # 工具/主题/存储/同步/鉴权 + PWA 注册
│       ├── data/content.js  # 内置每日内容素材库
│       ├── app.js      # 主控与路由
│       └── modules/    # 六大板块 + 设置中心逻辑
└── docs/               # 使用说明书 + 本指南
```

**唯一硬性要求**：托管空间必须支持「静态文件 + 普通 HTTP 访问」即可，不需要 Node、不需要数据库。

> 默认管理员账号：`admin` / `admin888`（首次登录后请立即在「设置中心 → 账号管理」中修改密码或新增账号）。

## 二、方式 A：CloudStudio 一键部署（推荐，最契合 7×24 需求）

适合：希望**零运维**、开箱即用、长期在线、可手机/电脑随时访问的用户。

1. 在本工作台的对话中执行「部署」操作（或运行内置的 CloudStudio 部署能力），选择本项目的 `ai-workbench/` 目录作为部署源。
2. 部署工具会自动创建一个云端沙箱工作区，把 `ai-workbench/` 内容上传并以静态文件服务器托管，生成访问地址（形如 `https://xxx.cloudstudio.app`）。
3. 部署完成后，浏览器打开该地址即可看到登录页。
4. 该站点运行在云端，**你的本地电脑关机也不影响访问**；如需下线/删除，可在「设置 → 数据管理 → 我发布的应用」中管理。

> 优点：全自动、无需配置服务器、自带公网 HTTPS 域名、长期稳定。
> 注意：云端沙箱为按需资源，若平台对空闲实例有回收策略，请按平台提示保持活跃或选择常驻方案。

## 三、方式 B：对象存储 + CDN（腾讯云 COS / 阿里云 OSS，适合公司内网+公网）

适合：需要**纳入公司自有云资源**、对内网/公网同时开放的正式场景。

### 腾讯云 COS 示例
1. 登录腾讯云控制台 → 对象存储 COS → 新建存储桶（所属地域任选，访问权限选「公有读私有写」）。
2. 进入存储桶 → 基础配置 → 开启「静态网站」：
   - 索引文档：`index.html`
   - 错误文档：`index.html`（单页应用回退，可选）
3. 把 `ai-workbench/` 目录下的**全部文件**上传到存储桶根目录（保持 `index.html` 在根、`assets/` 在根）。
4. 记下「静态网站域名」，如 `https://my-workbench-1234567890.cos-website.ap-guangzhou.myqcloud.com`，浏览器打开即可。
5. （可选）在 COS 绑定自定义 CDN 加速域名，或在公司内网通过反向代理转发该地址，实现内网访问。

### 阿里云 OSS 示例
1. 对象存储 OSS → 新建 Bucket（读写权限：公共读）。
2. Bucket 设置 → 静态页面：默认首页 `index.html`。
3. 上传 `ai-workbench/` 全部文件到 Bucket 根目录。
4. 通过 Bucket 的「存储空间域名」或绑定的自定义域名访问。

> 安全提醒：静态站点的 `index.html` 是公开可读的，但**业务数据存于访问者本地（localStorage）+ 你配置的云端同步服务**，服务端不保存任何账号与业务数据，无需担心源码泄露业务信息。账号密码经加盐哈希后仅存于各终端本地。

## 四、方式 C：任意静态托管平台 / 自有服务器

适合：已有 Vercel、Netlify、GitHub Pages、Cloudflare Pages 账户，或公司内有 Nginx。

### Vercel / Netlify / Cloudflare Pages
- 框架选「Other / 无框架」，构建命令留空，发布目录填 `ai-workbench`。
- 推送或拖拽上传即可，自动获得 HTTPS 公网地址。

### GitHub Pages
1. 把 `ai-workbench/` 内容推到仓库，仓库设置 → Pages → 源选 `main` 分支根目录。
2. 访问 `https://<用户名>.github.io/<仓库名>/`。
3. 注意：GitHub Pages 默认 URL 带子路径，本系统以相对路径加载资源，可直接使用。

### 公司内网 Nginx（最简配置）
```nginx
server {
    listen 80;
    server_name workbench.inner.company.com;   # 内网域名
    root /var/www/ai-workbench;                 # 指向 ai-workbench 目录
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
    # 如需公网，前置一层 HTTPS 反代或在 Nginx 上配置证书即可
}
```
把 `ai-workbench/` 整个目录拷贝到 `/var/www/ai-workbench` 后 `nginx -s reload`。

## 五、内网 + 公网同时访问的推荐架构

```
  手机/电脑浏览器
        │
   ┌────┴─────────────┐
   │  公网 HTTPS 域名  │  ← 方式B的CDN / 方式A的CloudStudio地址 / 方式C的平台域名
   │  或 公司内网域名  │  ← 方式C的Nginx内网域名 / 反代地址
   └────┬─────────────┘
        │
   云端静态托管（存放 index.html/app.html/assets）
        │
   终端本地 localStorage  ←→  你配置的云端同步服务（JSONBin.io / 自建REST）
```

- 静态资源只负责「界面与逻辑」，永远公开、无敏感信息。
- 真正的数据走「浏览器本地 + 你自己的云端同步端点」，账号密码仅存本地哈希。

## 六、上线后验证清单

部署后请逐项确认：

- [ ] 打开站点地址，出现登录页，默认账号 `admin/admin888` 可登录。
- [ ] 左侧导航 6 大板块 + 设置中心均可一键切换，移动端出现抽屉导航。
- [ ] 在「今日待办」新增一条，刷新页面数据仍在（本地持久化正常）。
- [ ] 切换浅色/深色主题生效，刷新后保持。
- [ ] 「设置中心 → 云端同步」填入同步端点后，多设备/多浏览器数据可合并。
- [ ] 手机浏览器打开，布局自适应、触控可点。

## 七、日常维护与更新

- **改内容/换素材**：编辑 `assets/js/data/content.js`（内置资讯、书摘、选题、运动计划等），重新上传/重新部署即可。
- **改功能**：编辑对应 `assets/js/modules/*.js` 或 `assets/css/style.css`，重新部署。
- **重新部署**：把更新后的 `ai-workbench/` 重新上传到托管空间覆盖原文件即可；CloudStudio 方式重新执行一次部署。
- **数据备份**：在「设置中心 → 数据管理 → 导出」下载 JSON 备份，存到个人网盘；换设备时「导入」即可恢复。

## 八、数据与安全要点（务必阅读）

1. **账号体系在终端本地**：账号/密码以加盐哈希形式存于各浏览器 localStorage，无中心账号库。换设备需各自注册/导入。
2. **业务数据默认本地**：待办、投资收藏、打卡、书库、选题等存于当前浏览器。要实现「多端同步」必须在「设置中心」配置云端同步端点。
3. **同步端点安全**：自建 REST 同步服务请加鉴权（Token/签名），避免被任意写入；JSONBin.io 请保管好私密 Bin ID，勿公开。
4. **无服务器漏洞面**：由于是纯静态站点，没有后端接口、没有数据库，天然免疫常见的服务端注入/越权类攻击。
5. **合规**：本系统仅作个人效率工具，请勿录入公司涉密数据到「未加密」的第三方同步服务。

## 九、把工作台「安装为桌面/手机 App」（PWA，无需下载安装包）

本系统已内置 **PWA（渐进式 Web 应用）**：无需去应用商店，用户在自己设备上「一键安装」后即可像微信一样拥有独立图标、全屏运行、可离线、自动更新。

### 桌面（Windows / macOS，Chrome 或 Edge）
1. 用 **Chrome / Edge** 打开站点地址（见上文部署结果）。
2. 地址栏右侧会出现一个「安装」图标（⊕ 或电脑小图标）；若没看到，点右上角 `⋮` →「**将此站点安装为应用** / Install 芋圆工作台」。
3. 确认后，桌面 / 开始菜单 / 任务栏即出现「芋圆工作台」图标，双击即全屏独立窗口打开，**断网也能用**（Service Worker 已缓存）。

### 安卓手机（Chrome）
1. 打开站点 → 点浏览器菜单 `⋮` →「**安装应用** / 添加到主屏幕」。
2. 桌面出现图标，点开即全屏 App（无浏览器地址栏）。

### iPhone / iPad（Safari）
1. 打开站点 → 点底部「**分享**」按钮 →「**添加到主屏幕**」。
2. 主屏出现图标，点开全屏运行。

> 说明：App 名称与图标来自 `manifest.json`（`name` / `short_name` / `icons`）。当前品牌名为「芋圆工作台」，淡蓝风格图标。若要改成你自己的品牌名或图标，改这个文件即可，重新部署后生效。

## 十、开启多端同步（JSONBin.io 免费云，桌面↔手机共享数据）

默认数据存在各设备本地（localStorage），彼此独立。**要像微信一样在桌面和手机间同步，需配置一个云端同步后端**。推荐免费、无需服务器的 **JSONBin.io**。

### 步骤
1. 打开 [jsonbin.io](https://jsonbin.io) 免费注册（邮箱即可）。
2. 进入 Dashboard → **Create a Bin**，随便存一个 `{}` 并保存，得到 **Bin ID**（URL 中 `b/xxxx` 那段）。
3. 复制页面上的 **Secret Key / Master Key**（即 `X-Master-Key`）。
4. 在**任意一台设备**的工作台 →「设置中心 → 云端同步」：
   - 同步方式：选 **JSONBin.io**
   - **Bin ID**：粘贴第 2 步的值
   - **Master Key**：粘贴第 3 步的值
   - 自动同步：开
   - 点「保存」，再点「**立即同步**」上传当前数据。
5. 在**另一台设备**（手机 / 另一台电脑）登录后，同样填入**相同的 Bin ID + Master Key**，点「立即同步」即可拉取 / 合并数据。

### 同步行为
- 采用「**按记录时间戳合并**」策略，多设备可同时使用，后写覆盖先写；删除以墓碑方式传播，不会被旧数据复活。
- 支持「自动同步（每 15 秒防抖）」与「联网恢复即触发」，也可手动「立即同步」。

### 安全
- 妥善保管 **Master Key 与 Bin ID**，勿公开；JSONBin 免费额度对个人日常使用足够。
- 如需数据完全自管，可在「同步方式」改选「自定义接口」，填入你公司内网 / 自有服务器的 REST 地址与 Token（见 `core.js` 的 `Sync` 模块约定）。
